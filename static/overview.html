Console Overview

How it works

A multi-agent support desk: a triage agent classifies each ticket and hands it to a specialist, every risky action is checked against a deterministic guardrail before it's allowed to run, and anything uncertain or high-risk pauses for a human to review.

Architecture

Key features

Multi-agent routing

Triage classifies each ticket; billing, technical, and account specialists each handle their own domain with their own tools.

Real tool use via MCP

Specialists call real MCP-backed tools — a SQLite CRM, a searchable knowledge base, an email/notify service.

Human-in-the-loop

Risky actions genuinely pause graph execution via LangGraph's interrupt() and wait for a real decision.

Layered guardrails

PII redaction, prompt-injection detection, and output validation — with tool-call allowlisting as the primary defense.

Measured, not assumed

A 20-ticket eval harness scores routing accuracy, escalation precision/recall, and resolution correctness.

Shipped as a service

FastAPI + Docker packaging — a real, runnable service, not just a script.

Known limitations

  • Retrieval — knowledge base search is keyword-based, not embeddings.
  • Persistence — the checkpointer is in-memory; pending tickets are lost on restart.
  • Architecture — MCP servers run as subprocesses (stdio) in one container, not as separate networked services.
  • Security — no auth or rate-limiting on the API yet; not intended for public deployment as-is.
